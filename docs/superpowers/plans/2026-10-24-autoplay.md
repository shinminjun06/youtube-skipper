# Verified Autoplay Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. Track task results below.

**Goal:** Recognize, align, execute and verify consecutive legal Block Blast moves.
**Architecture:** Pure Java recognition/planner/control core with native Kotlin
MediaProjection and continued AccessibilityService strokes.
**Tech Stack:** Kotlin 2.0.21, Java 17, Android API 30+, AGP 8.7.3, JUnit4.
**Spec:** docs/superpowers/specs/2026-10-24-autoplay-design.md

## Global Constraints
Only blockblast-auto-build; no network permission; preserve manual stop; no claim
of real game validation. Do not publish keystores. User authorizes commit and CI.

## Review Focus
1. Mid-drag stop or app switch must release away from the board.
2. Unknown colors or screenshot geometry must not become an empty board.
3. Line-clearing animations and final-hand refresh require stable exact results.
4. Screenshot copies must not outlive closed Image buffers or leak bitmaps.
5. Search must fit a bounded time/work budget on the capture worker.
