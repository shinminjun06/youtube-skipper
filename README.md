# Block Blast Advisor + Auto v1.4.5

Android 11+ 전용 오프라인 Block Blast Classic 게임판 분석 앱입니다. **추천 모드**와 **자동 플레이 모드**를 같은 앱에서 선택할 수 있습니다.

- **기본값: 추천** — 현재 판과 손패에 맞는 추천 위치를 테두리로 표시하고 사용자가 직접 블록을 놓습니다. 게임에 자동 터치를 보내지 않습니다.
- **모드: 자동** — 사용자가 의도적으로 선택하고 ▶ 시작을 누른 경우에만 AccessibilityService가 게임에 드래그를 전송합니다. 블록을 잡았는지, 위치가 맞는지, 실제 놓인 블록과 게임판이 예상과 일치하는지를 차례로 검증합니다.
- 불확실한 화면, 잘못된 설치, 전체 손패 배치 불가능, 앱 전환, 제스처 취소, 시간 초과 시 자동 조작을 **중지**합니다. 게임 오버 없이 무제한 플레이를 보장하지 않습니다.

개발 브랜치: `blockblast-autoplay-build`. 기존 **추천 전용 v1.2.0**의 소스는 `blockblast-auto-build` 브랜치에 그대로 보존했습니다. 기본 `main` 브랜치는 변경하지 않습니다.

## 사용법

1. [오토플레이 전용 빌드 페이지](https://github.com/shinminjun06/youtube-skipper/actions?query=branch%3Ablockblast-autoplay-build)에서 **Build BlockBlast Advisor + Auto APK**가 초록 체크로 완료된 실행을 열고 **BlockBlastAutoPlay-apk** ZIP을 다운로드합니다. ZIP을 풀고 **BlockBlastAutoPlay-v1.4.5.apk**를 설치하세요. 구버전과 혼동하지 마세요.
2. 홈 화면에서 **Block Blast AutoPlay** 아이콘을 실행해 **v1.4.5**이라고 표시되는지 확인합니다. 기존 **Block Blast Advisor**(v1.2)는 다른 앱으로 남아 있습니다. 기존 Advisor의 접근성 서비스를 끄고 **Block Blast AutoPlay** 접근성을 연결한 다음 **전체 화면 공유 시작**을 승인합니다.
3. 앱 첫 화면에서 **자동 플레이 모드 선택**을 누른 뒤 Block Blast Classic의 세로 화면을 엽니다. 자동 모드에서는 하단에 고정되는 플로팅 창에서도 **모드: 추천** 또는 **모드: 자동**을 전환할 수 있습니다.
4. **▶ 시작**을 누릅니다. 추천에서는 초록색 칸을 보고 수동으로 놓습니다. 자동에서는 플로팅 창이 사라지고, 앱이 블록을 잡고 설치를 검증합니다. 조작창이 숨겨져 있는 것은 정상입니다.
5. **자동 플레이 중에는** Android 알림 패널의 **종료** 버튼으로 즉시 중지하세요. 중지되면 플로팅 창이 다시 나타납니다. 추천 모드에서는 기존 ■ 중지 버튼을 이용할 수 있습니다.
6. 추적 실패 시 앱의 **위치 측정 실패 진단 파일 저장**을 이용해 원인 분석용 ZIP을 저장할 수 있습니다.

## v1.4.5 — 화면 가장자리 과민 안전 중단 개선

- **발생 조건**: 1.4.4에서는 움직이는 조각 외곽이 화면 경계 안쪽의 작은 안전 여백을 단 몇 픽셀이라도 넘으면 `DragResponse.correction()`이 예외를 던지고, 앱이 `화면 가장자리 위치를 확실히 확인할 수 없어 안전 정지`를 표시했습니다.
- **이번 변경**: 정확한 전체 모양을 추적한 후 경계에서 최대 0.18칸(최대 16px)만 벗어난 경우, 목표 방향이 화면 안쪽이라면 손가락을 해당 축에서 화면 안쪽으로 이동시키는 것만 허용합니다. 새 이미지를 다시 확인하기 전에는 블록을 놓지 않습니다.
- 과도하게 잘린 조각, 화면 바깥으로 더 이동하라는 명령, 부정확한 좌표는 종전처럼 중단합니다. 목표 칸 미리보기와 실제 배치 후 게임판/손패 검증도 그대로 둡니다.
- 실패 진단 ZIP에 `servoFailureDetail`을 추가했고 로그에는 블록의 추적 원점, 목표 위치, 조각 크기와 화면 크기를 기록해 동일 문제가 반복되면 경계 오차와 추적 오류를 구별할 수 있게 했습니다.
- 3×3 L자 블록의 미세한 경계 초과, 화면 위쪽 복귀, 화면 밖 방향 명령 거부, 심한 클리핑 거부를 위한 회귀 테스트를 추가했습니다.
- 실제 사용자의 해당 중단 화면만으로 당시 움직이는 블록의 정확한 좌표까지 복원할 수는 없습니다. **개선 효과는 실기기 재시험으로 확인해야 합니다.**

## v1.4.4 — 안전하게 게임판 격자 재탐색 줄이기

- **기존 1.4.3 자동 드래그 안전장치 유지**: 정확한 모양/손패 슬롯별 학습, 화면 가장자리 직접 이동 제한, 실제 블록 전체 추적, 놓기 전 위치 및 놓은 후 보드 검증, BASE/QUICK/FAST 속도 단계는 그대로 둡니다.
- **격자 좌표 재사용**: 직전 정식 인식 프레임의 left/top/cell 값으로 8×8 선과 상하 경계를 다시 검사합니다. 기존 `gridScore` 기준을 통과하면 매 프레임 큰 화면 영역에서 게임판 위치를 다시 찾는 과정을 생략합니다. 점수 기준을 통과하지 못하거나 화면 크기가 바뀌면 기존 전체 탐색으로 돌아갑니다.
- **블록 상태는 캐시하지 않음**: 게임판 64칸 점유와 현재 손패 모양은 언제나 새 화면에서 다시 인식하므로, 다음 블록을 놓거나 줄이 제거된 상황을 이전 데이터로 조작하지 않습니다.
- 화면 테마별 스크린샷, 손패 변경, 잘못된 힌트 좌표, 검은 캡처를 검증하는 회귀 테스트를 추가했습니다.
- 기기별 속도/CPU 개선폭은 **실기기에서 아직 측정하지 않았습니다**. CI 성공은 무중단 자동 배치 성공을 의미하지 않습니다.

## v1.4.3 — 속도 향상, 기존 안전 검증 유지

- **정상 동작하는 v1.4.2의 블록 인식·반응 배율 학습·조각 배치·안전 검증 알고리즘은 유지합니다.** 이제 속도가 일정하게 고정된 것이 아니라, 성공한 실제 배치 횟수에 맞춰 조절됩니다.
- **안전 기본 속도:** 실행을 처음 시작하면 v1.4.2와 동일한 긴 누르기 160ms, 첫 드래그 500ms, 이동 확인 320ms, 위치 보정 350ms, 놓기 150ms, 화면 검사 대기 160ms를 사용합니다.
- **중간 속도:** 실제로 배치된 게임판과 소모된 손패가 2회 연속 정상 검증되면 첫 드래그 405ms, 이동 확인 265ms, 위치 보정 295ms 등으로 단축합니다.
- **빠른 속도:** 5회 연속 정상 배치되면 첫 드래그 345ms, 이동 확인 225ms, 보정 260ms, 놓기 130ms, 화면 검사 대기 115ms까지 줄입니다. **잡기용 160ms 누름은 절대 줄이지 않습니다.**
- **자동 감속:** 블록을 다시 찾아야 하거나, 보정이 과도하거나, 실제 놓은 뒤 판이 변하지 않아 재시도해야 하는 경우 즉시 v1.4.2 기본 속도로 복귀합니다. 계산기의 편의 점수나 Android 제스처 완료만으로 가속하지 않습니다.
- 화면 및 블록 상태를 안정적으로 확인한 다음에만 손가락을 놓으며, 놓은 후 실제 게임판 검증은 완전히 동일합니다. 자동 추천 모드도 변경하지 않았습니다.
- **오프라인 시간 설정 비교:** 일반적인 잡기+이동+탐색+보정+놓기의 동작 시퀀스를 가정하면 제스처·화면 대기 시간 설정 합계가 **2,440ms → 1,855ms(약 24% 감소)**입니다. **실제 게임에서 한 수를 24% 빨리 놓는다는 실측 주장이 아닙니다.** 앱은 검증 완료마다 실제 제스처 횟수와 배치 소요 시간을 기록합니다.
- Android 접근성 제스처는 계속 `dispatchGesture`/`continueStroke`를 사용하며, 실제 입력의 성공·완료 콜백과 게임에서 배치가 성공했다는 판정은 별개로 취급합니다.
- 회귀 테스트는 빠른 속도 전환 조건, 실패/불확실 시 속도 복구, 최소 누름·확인 간격과 기존 모든 인식/설치 검증을 검사합니다.
- 현재 속도를 확인하려면 앱의 상태 또는 진단 ZIP에서 `gestureSpeedTier` 필드를 확인할 수 있습니다 (`BASE` / `QUICK` / `FAST`). 자동 모드 진행 중에는 플로팅 창이 숨겨지며 Android 알림의 종료 버튼은 그대로 사용할 수 있습니다.

## v1.4.2 — 실측 1.5배 이동 반응을 고려한 화면 피드백 제어

- 업로드된 **v1.4.1 진단 ZIP (8)**에서 `ALIGN / NO_HELD_MATCH`: 초록색 세로 5칸 블록이 오른쪽으로 너무 멀리 이동해 화면 오른쪽에서 잘렸습니다. 처음 캡처의 확대 블록은 약 `(322,1075)`, 마지막은 약 `(667,715)`, 목표는 약 `(600,608)`이었습니다. 검증된 배치 0회, 이번 블록은 **학습형 직접 이동이 아닌 기본 단계 이동**을 사용했습니다.
- 당시 손가락의 누적 움직임은 약 **오른쪽 229픽셀 / 위로 240픽셀**이었으나 실제 블록은 **오른쪽 345픽셀 / 위로 360픽셀** 이동했습니다. 게임의 실제 반응이 양축에서 약 **1.5배**였는데 기존 보정 알고리즘은 위치 오차에 근접한 손가락 이동을 보내 과잉 조작을 유발했습니다.
- 이제 블록 전체의 모습과 이동 방향이 명확히 일치하는 **짧은 첫 번째 잡기 확인**에서 `실제 조각 이동량 ÷ 손가락 명령량`을 측정합니다. 그 결과를 현재 드래그에만 적용해 이후 보정 명령을 계산하며, X/Y축의 개별 반응도 관찰합니다. 잘못된 방향·비정상적으로 큰 응답·움직이지 않은 프레임은 학습하지 않습니다.
- 실측 자료가 아직 없을 때는 기존 반복 진단의 1.4~1.5배 반응을 반영한 보수적 초기값으로 시작합니다. 이번 드래그의 반응값은 다른 게임 세션이나 다음 블록에 무조건 재사용하지 않습니다.
- 화면을 벗어나는 블록 이동을 막도록 **예상 블록 전체 직사각형과 캡처 화면 경계**를 이용해 각 축 이동량을 제한합니다. 이미 블록이 잘렸거나 위치가 불확실하다면 임의로 놓거나 계속 이동시키지 않고 정지합니다.
- 초록색 1×5 조각과 진단 메타데이터의 정확한 화면 크기(720×1560), 79.875픽셀 칸 크기, 약 1.5배 응답을 합성한 회귀 테스트에서 기존 1:1 보정은 조각을 오른쪽 경계 밖으로 보내지만 새 보정은 화면 안을 유지하며 두 번의 피드백 조작 후 목표 위치에 접근하는지 검사했습니다. 개인정보가 담길 수 있는 진단 스크린샷은 공개 저장소에 올리지 않았습니다.
- 진단 ZIP에는 `fingerToSpriteGainX/Y`와 `visualResponseMeasured`가 포함돼, 다음에는 추적 오류뿐 아니라 이동량 자체의 문제인지도 구분할 수 있습니다.
- APK 빌드 통과는 실제 휴대폰에서 장시간 연속 자동 배치가 성공한다는 뜻이 아니므로, 실기기 검증이 계속 필요합니다.

## v1.4.1 — 세로 5칸 집기 인식 실패 해결

- **v1.4.0 사용자 진단 ZIP (7)**: `PICKED / NO_HELD_MATCH` 오류. 2번 초록색 세로 5칸 블록이 실제로 약 **78픽셀 왼쪽 이동**했고, 요청한 이동은 약 **52픽셀 왼쪽**으로 방향이 일치했습니다. 오버레이 가림은 없었습니다.
- 실제 화면 확인에서 **확대된 초록색 블록의 5칸 중 3개 중심이 원래 작은 초록색 트레이 블록과 겹쳤습니다.** 확대된 블록 내부 45개 색상 표본 중 37개가 새롭게 바뀌었지만, 기존 예외 검사에는 **최소 3개 중심의 신규 색상 변화**가 필요해 2개 신규 중심만 가진 실제 블록을 거부했습니다.
- 단순히 중심 검사 기준을 전체적으로 낮추지 않고, **선택된 해당 조각의 작은 트레이 영역에 속한 중심만 기존 동일 색상을 허용**합니다. 게임판이나 다른 위치의 원래 같은 색상 타일은 예외 처리하지 않습니다. 여전히 모든 큰 블록 칸의 형태/색상, 최소 2개 신규 중심, 55% 이상의 신규 색상 표본, 고유한 후보, **명령 방향·이동량 일치**를 검증합니다.
- 합성된 720×1560 이미지/트레이 좌표를 이용해 실제 오류와 **움직이지 않은 블록·반대방향 이동·다른 위치의 기존 같은 색상·복수 후보**를 함께 회귀 검증합니다. 실제 사용자 진단 PNG를 공개 저장소에 올리지 않았습니다.
- 첫 이동 방향·형태가 명확하면 **재측정 제스처를 추가로 보내기 전에** 선택된 대기 조각 영역만 제외하고 같은 화면 쌍을 재검사합니다. 따라서 이번 오류와 같은 상황에서 불필요한 왕복 움직임을 줄일 수 있도록 개선했습니다.
- 진단상 이 세션에는 **1회의 검증 성공**이 있었고, 실패한 세로 5칸은 **학습형 직접 이동이 아니라 기본 안전 경로**에서 발생했습니다. v1.4.1은 이 초기 집기 인식 경로를 수정했습니다.
- 실제 연속 자동 배치 성공률은 휴대폰에서 검증해야 하며, 다음 진단에는 v1.4.0에서 추가한 이동 시간·제스처 수·경로별 성공 계측이 그대로 기록됩니다.

## v1.4.0 — 방법 비교 후 적용한 하이브리드 자동 드래그

### 왜 구조를 바꾸었나

이전 v1.3.x 계열은 모든 블록에 대해 고정 대기 위치로 길게 드래그하고, 좌우로 추가 시험 이동한 뒤, 2칸/62% 제한으로 여러 번 보정해 목표에 도달했습니다. 실제 진단에서 손가락과 스프라이트의 위치 관계, 원본 트레이 썸네일 겹침, 화면 오버레이 가림, 칸 흡착과 렌더 지연에 따른 실패가 반복됐습니다.

공식 Android 입력 API인 `dispatchGesture`/`continueStroke`를 유지하면서 **성공한 배치로만 학습하는 보정값 + 목표까지 직접 이동 + 마지막 화면 재검증** 방식을 도입했습니다. 선택 근거와 다른 방식의 장단점, 측정 한계를 [drag-method-study.md](docs/drag-method-study.md)에 작성했습니다.

### 동작 원리

1. **처음에는 검증된 기존 방식:** 완전히 잡혔는지와 실제 블록 이동을 확인하고, 오류가 클 때도 3칸 이하의 적응형 보정으로 목표에 접근합니다. 목표가 가까우면 보정 폭을 줄입니다.
2. **검증 성공만 학습:** 목표 미리보기가 올바르고 손가락을 놓은 뒤 게임판 및 소모된 손패까지 일치한 경우에만, 터치 위치와 블록 그림 위치의 관계를 저장합니다. 화면에서 보이기만 했거나 실패한 움직임은 학습하지 않습니다.
3. **일관된 2회 성공 이후 직접 이동:** 같은 손패 슬롯에서 서로 일치하는 2회 성공이 확인되면, 조각 크기에 맞춰 정규화된 오프셋으로 목표 손가락 좌표를 예측해 한 번에 움직입니다. 계속 누르고 있으므로 잘못 예측돼도 검사 전에는 놓지 않습니다.
4. **예측 오류에는 다시 보정:** 화면에 표시된 실제 조각이 목표 위치와 다르면 최대 이동량을 제한하여 수정합니다. 불확실하거나 후보가 겹치면 중단합니다.
5. **실제 배치 재확인:** `locateNear + targetCellPreview`와 `MoveVerifier` 검사는 그대로 유지합니다. 오프셋이 달라지거나 화면 크기가 변하면 빠른 경로를 해제합니다.

처음부터 안전하게 검증된 배치 2회가 없으면 **빠른 모드가 아니라 기본 안전 모드로 작동**합니다. 자동 플레이 중 플로팅 창은 이전처럼 숨기며 Android 알림의 종료로 멈출 수 있습니다.

### 실제로 측정한 것과 아직 측정하지 못한 것

- **결정적 가상 드래그 244개 조건**: 기존 2칸/62% 보정 914회, v1.4.0 적응형 보정 678회, 모델상 보정 동작 25.8% 감소. 손가락 움직임에 대한 게임 화면 반응률을 0.75/1.0/1.25/1.5로 가정한 합성 테스트입니다.
- 같은 테스트에 캘리브레이션 초기 상태, 2회 합의, 슬롯별 격리, 화면 셀 크기 변화, 엇갈린 학습값/NaN, 화면 밖 예측 차단 등을 포함합니다.
- **실제 게임에서 25.8% 빨라졌다거나 설치 성공률이 상승했다는 주장은 아닙니다.** 실기기 배치 성공 로그가 필요합니다.
- v1.4.0은 실제 성공한 배치마다 **직접/기본 모드, 실행 제스처 횟수, 배치 시간, 누적 평균**을 Android 로그에 기록하며, 실패 ZIP에도 해당 계측 요약을 포함합니다. 이를 통해 다음 검증에서 실제 성능을 비교할 수 있습니다.

## v1.3.7 실제 이동한 빨간 블록을 놓치는 오류 수정

- 사용자가 올린 v1.3.6 진단 ZIP은 `PICKED / NO_HELD_MATCH`. 게임판이 차 있는 상태에서 **2번 빨간색 4칸 L 조각**을 집어 움직였지만, 앱은 움직임 확인에 실패했습니다.
- **진단 PNG의 실제 시간 순서**는 `before.png → probe.png → held.png`입니다. `probe.png`의 확대된 빨간 L 원점 약 `(340,1034)`이 `held.png`에서 약 `(262,1034)`으로 **왼쪽 78픽셀** 이동했습니다. 명령한 왼쪽 52픽셀과 방향이 맞습니다.
- 실패 원인은 **원래 대기 중인 작은 빨간 L의 색상과 확대된 블록이 겹쳤기 때문**입니다. 현재 블록 중심 4개 중 2개가 집기 전 사진의 빨간색과 이미 일치하여, 모든 중심이 새로 바뀌어야 한다는 기존 추적 조건이 실패했습니다.
- 기본 탐색의 엄격한 색상·형태 검사는 유지합니다. 최초 이동 검증이 실패하여 **반대 방향으로 한 번 재측정하는 상황에만** 완전한 모양, 절반 이상의 새로운 중심, 55% 이상의 새로운 색상 표본, 실제 명령 방향과 일치하는 움직임을 함께 검사하여 재탐색합니다.
- 손가락 주변 넓은 검색 영역을 검사하여 **동일한 모양의 후보가 두 개 이상이면 성공 처리하지 않습니다**. 이 복구는 집힌 블록을 다시 찾는 데만 사용되며, 목표 위치에 블록을 놓기 전에 수행하는 엄격한 검증과 실제 설치 후 게임판 검증은 변경하지 않았습니다.
- 업로드된 개인 게임 화면은 저장소에 공개하지 않았고, 해당 좌표·대기 블록 겹침과 안전 실패 사례를 합성 데이터 회귀 테스트에 추가했습니다.
- CI 테스트/빌드가 통과해도 실제 휴대폰에서 연속 자동 배치가 보장되지는 않습니다.

## v1.3.6 긴 블록이 플로팅 창에 가려지는 오류 수정

- 사용자가 제공한 **v1.3.5 진단 ZIP**은 `NO_HELD_MATCH / PICKED`이며, 실제로 블록을 못 잡은 게 아닙니다. **파란색 세로 5칸 블록**은 처음 잡힌 뒤 약 한 칸(78px) 이동했지만, 화면 오른쪽 아래의 불투명한 플로팅 창이 아래 **2칸의 중심**을 가려 5칸 전체 형태 검증을 통과할 수 없었습니다. 명령은 52px 왼쪽, 실제 블록도 왼쪽으로 움직인 증거가 있습니다.
- 하단 또는 상단에 패널을 옮기는 기존 대응은 특정 모양/위치의 다른 블록을 다시 가립니다. **자동 모드의 ▶ 시작 이후에는 불투명한 조작창과 추천 테두리 모두 Android 화면 및 화면 캡처에서 숨김 처리**합니다. 자동 실행이 멈추거나 중단되면 조작창을 다시 표시합니다. 추천 모드는 종전처럼 하이라이트와 조작 버튼을 유지합니다.
- 자동 실행 중 긴 블록이 가려지지 않도록 캡처를 정리하면서도, **모든 조각 중심에 대한 엄격한 움직임 확인**과 **실제 놓은 뒤 보드 검증**은 그대로 유지합니다. 흐릿하거나 불완전한 블록을 무조건 성공 처리하지 않습니다.
- **자동 모드를 멈추려면 Android 알림 패널의 `Block Blast Advisor + Auto` → `종료`**를 이용하거나 앱을 열어 `정지`를 누르세요. 숨긴 플로팅 창을 누르는 방식으로 멈출 수는 없습니다. 안전 취소 시 숨긴 패널의 옛 좌표 대신 시스템 화면 모서리에 종료 제스처를 보내 게임판에 불필요한 탭을 만들지 않습니다.
- 사용자 스크린샷을 공개 저장소에 올리지 않았으며, 합성 화면 회귀 검사와 Android 기기용 UI 숨김/복원 테스트를 추가했습니다. **실제 게임에서 연속 자동 설치가 성공하는지는 아직 검증되지 않았습니다.**

## v1.3.5 세로 2칸 블록 잡기 오류 수정

- v1.3.4 사용자 진단 ZIP의 **NO_HELD_MATCH / PICKED** 상황: 빈 게임판의 보라색 세로 2칸 블록을 정상적으로 잡았고, 진단 영상에서 블록 외곽의 가로 좌표는 `511..587 → 433..509`로 **78픽셀 왼쪽 이동**했습니다. 앱에서 요청한 이동은 약 `52픽셀`이었습니다.
- 기존 탐색기는 이전 손가락 위치 `416`에서 오른쪽으로 **1칸(약 80픽셀)**까지만 검색해 블록 원점 `511`을 놓쳤습니다. 실제 블록 움직임은 정상인데도 **잡지 못했다고 판단**했던 문제입니다.
- 보통은 원래의 빠른 손가락 근처 검색 범위를 사용하고, 찾지 못한 경우에만 **왼쪽 추가 2.5칸, 오른쪽 3칸까지 넓혀 재검색**합니다. 손가락 대비 게임의 가로 드래그 보정값이 달라도 새로 나타난 실제 조각을 찾도록 했습니다.
- 넓혀 찾았더라도 조각의 색상, 전체 모양, 새로 생긴 화면 픽셀, **명령한 이동 방향과 크기**가 모두 일치해야 잡기 성공으로 인정합니다. 정지된 조각·반대 방향 이동은 인식하지 않습니다.
- 진단 이미지 원본은 공개 GitHub에 넣지 않고, **해당 720×1560 좌표와 블록 이동을 합성한 테스트**로 회귀 확인합니다. 실제 게임에서 끊김 없는 자동 플레이 성공률은 아직 실기기 검증이 필요합니다.

## v1.3.4 노란색 T자 블록 추적 오류 개선

- 진단 ZIP v1.3.3의 `NO_HELD_MATCH / ALIGN`은 한 번의 드래그 이후 노란 T자 블록이 게임판보다 높이 올라가고, 플로팅 상태 창이 블록의 **4개 중심 중 3개를 가린 상황**입니다. 실패 당시 좌표는 손가락 약 `(346,574)`, 블록 약 `(326,35)`, 목표 `(361,366)`이었습니다.
- 자동 모드에서는 플로팅 조작창을 **화면 최하단(블록 트레이 아래)**으로 자동 이동합니다. 상태 메시지가 길어져 창 높이가 바뀌어도 다시 하단에 맞춥니다. 자동 입력 중에는 플로팅 창 드래그를 잠급니다. 정지 버튼은 계속 누를 수 있습니다.
- 기존 보정은 목표-현재 블록 오차를 한 번의 손가락 이동으로 그대로 전달했습니다. **최대 2칸, 오차의 62%씩 단계 보정**하도록 변경해 큰 점프가 게임의 손가락-블록 수직 간격을 왜곡해 화면 위로 날아가는 일을 줄입니다. 최대 10회 보정과 14.5초 제스처 안전 타임아웃을 적용합니다.
- 노란 T자 블록 가림 및 과도한 이동을 **사용자 스크린샷을 공개하지 않은 합성 테스트**로 확인합니다. 인식이 불확실하면 블록을 놓지 않고 정지하는 기존 안전장치를 유지합니다.
- 자동 모드와 별개의 추천 전용 앱은 변경하지 않았습니다. **실제 기기에서 연속 성공은 아직 추가 검증이 필요**합니다.

## v1.3.3 자동 플레이 정렬 보정

- 사용자가 보내준 v1.3.2 진단 ZIP은 `CORRECTION_LIMIT / ALIGN`으로, 주황색이나 파란색 블록이 아닌 **보라색 2×2 블록**을 **5번 보정하고도** 끝내 놓지 못한 상황입니다.
- 실패 스크린샷에는 조각이 목표 5열·2행의 네 칸을 이미 덮고 있었습니다. **올려준 실제 영상 프레임을 오프라인 색상 비교한 결과 목표 내부 16/16 지점이 실제 보라색 조각 색상과 일치**했지만, 그림의 윗변은 게임이 목표보다 약 18픽셀 위에 그렸습니다.
- `DragAlignment.targetCellPreview`는 **배치 가능성 + 4개 조각 칸 내부의 16개 색상/변화 검사**를 결합합니다. 블록 그림이 목표에서 최대 0.32칸 벗어나도 **목표 인근 추적이 유일하고 180ms 이상 안정적**이며 네 칸 모두 올바른 색상으로 덮인 경우에만 놓습니다.
- 다른 칸에 있거나 0.55칸 이상 벗어난 조각, 다른 색상이나 정지된 그림은 조작을 승인하지 않습니다. 놓은 뒤에는 여전히 실제 게임판/손패를 검증하고 틀리면 자동 플레이를 중단합니다.
- 실패 진단 ZIP에 마지막 추적 좌표와 목표 칸 미리보기 인식 여부를 기록해 다음 장애 진단이 더 명확해졌습니다.
- 업로드한 개인정보 포함 가능성이 있는 실제 스크린샷 파일은 GitHub에 공개하지 않고, 합성 화면으로 회귀 테스트를 작성했습니다.

## v1.3.2 정렬 실패 수정

- 실제 사용자가 업로드한 v1.3.1 진단 ZIP의 `ALIGN / NO_HELD_MATCH` 사례를 조사했습니다. **보라색 2×2 조각은 실제로 들려 있었으나 약 (523, 273)에 표시되어 목표 (440, 524)와 멀었습니다.** 기존 코드는 목표 부근만 검색했습니다.
- 정렬 중 목표 인근에서 블록을 못 찾을 때는 **전체 손에 들린 영역을 다시 검색**해 위치를 재보정합니다.
- 플로팅 상태 창이 블록 첫째 줄을 가린 경우 36개 색상 표본 중 6개가 가려져도, **모든 블록 중심부가 새로 나타났고 외곽 경계가 정상인 경우에만** 복구 위치를 허용합니다.
- **실제 블록 놓기에는 이전과 같은 엄격한 목표 위치 일치 검사가 반드시 필요**합니다. 복구용의 느슨한 검색 결과만으로 블록을 놓지 않습니다.
- 개인정보가 담길 수 있는 진단 스크린샷은 저장소에 넣지 않고 **합성 회귀 테스트만** 추가했습니다.
- 코어 및 APK 빌드는 CI 결과로 확인하고, 실제 기기 성공률은 추가 검증이 필요합니다.

## v1.3.2 변경 사항

- **설치 혼동 방지:** 앱 ID를 `com.pivotry.blockauto.autoplay`로 분리했고, 설치 앱 이름을 **Block Blast AutoPlay**로 변경했습니다. 기존 추천 전용 `com.pivotry.blockauto`는 그대로 남습니다. Android 접근성 설정에서 두 서비스를 동시에 켜지 마세요.
- **명확한 모드 버튼:** 플로팅 창뿐 아니라 앱 첫 화면에도 **자동 플레이 모드 선택 / 하이라이트 추천 모드 선택** 버튼을 추가하고, `현재 모드` 상태를 표시합니다.
- **버전 표시:** 앱 첫 화면과 APK 파일명에 **v1.3.2**이 명시됩니다. v1.2 화면이 뜬다면 여전히 기존 Advisor 앱을 실행한 것입니다.


- v1.2.0의 3개 손패 탐색, 콤보 점수 근사 및 생존 평가, 기기 내 **COMBO** 텍스트 자동 인식을 계승합니다. 다른 버전에서는 실제 점수 규칙이 다를 수 있습니다.
- 기존 v1.0.0의 Android 이어붙이기 드래그 제스처를 **선택형 자동 모드**로 복원했습니다. 기본 모드에서는 자동 터치가 불가능하도록 실제 동작부에서 검사합니다.
- 이전 진단의 **52px 요청 / 약 78px 렌더 이동**처럼 게임의 조각이 칸 단위로 보정되어 움직여도 잡힌 블록 전체의 방향·위치가 일치하는지 검증합니다. 정지된 트레이나 미리보기만으로는 손에 잡았다고 판단하지 않습니다.
- 이동하는 블록의 목표 위치를 재관측하고, 위치를 보정한 후에만 손가락을 놓습니다. 배치 이후 게임판과 남은 조각이 예상과 일치하지 않으면 멈춥니다.
- 추천 모드에서는 하이라이트 픽셀을 캡처에서 보정하고, **변화 없는 게임판을 반복 계산하지 않도록 캐싱**합니다.
- 메인 앱 내 콤보 수동 입력이 필요하지 않습니다. OCR이 놓치는 순간에는 기존 확인된 배치 기록으로 콤보를 추적합니다.

## 검증과 한계

- `bash tools/check-core.sh` — Java 17: 실제 화면 인식, 이동량 오차, 고득점 탐색, 점수 텍스트 보호, 진단 ZIP 회귀 테스트
- `gradle :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug` — Android SDK 35
- `.github/workflows/gesture-integration.yml` — 수동 실행하는 Android 에뮬레이터 제스처 통합 검사
- **빌드 성공과 코어 테스트 통과만으로 실제 휴대폰 게임에서 터치 성공이 입증되는 것은 아닙니다.** 게임 버전, UI 크기, 화면 공유 렌더링과 애니메이션에 따라 추가 조정이 필요할 수 있습니다.
- 앱에서 사진이나 텍스트를 외부 서버로 전송하지 않습니다. ML Kit의 텍스트 인식 모델은 APK에 포함됩니다. Android 루트가 필요하지 않습니다.
