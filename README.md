# Block Blast Auto 0.5.2

Android 11+용 화면 인식 기반 자동 배치 앱입니다. `blockblast-auto-build` 브랜치의 독립 프로젝트이며 저장소의 main 프로젝트는 변경하지 않습니다.

## 사용

1. APK를 설치하고 앱에서 **접근성 설정 열기**를 눌러 Block Blast Auto를 허용합니다.
2. 앱에서 **화면 공유 시작**을 누르고 **전체 화면** 공유에 동의합니다.
3. 블록 블라스트를 세로 화면으로 열고 우측 위 **▶ 자동 시작**을 누릅니다.
4. 정지 버튼이나 알림의 종료 버튼으로 중단할 수 있습니다. 회전·앱 전환·공유 종료 후에는 다시 시작합니다.

화면 공유와 접근성은 사용자 동의 후에만 사용합니다. 화면은 메모리에서 분석하고 외부로 전송하지 않습니다. 인터넷, 저장소, 루트 권한을 사용하지 않습니다. 접근성의 화면 내용 조회는 조작 대상 앱을 확인하는 데 사용합니다.

## 0.5.2 잡힌 블록 위치 측정

- 323831.png의 정지 문구는 손패 인식 이후 위치 측정 단계에서 발생합니다. 화면에는 이미 원위치로 돌아온 블록만 보이므로 실제 잡힌 위치/실패 단계는 사진만으로 확정할 수 없습니다.
- 기존 준비 위치 탐색은 블록 원점이 판의 하단보다 위에 있으면 제외했습니다. 현재는 화면 높이를 탐색하고, 모든 셀의 중앙이 조작 전 화면과 달라야 한다는 증거를 요구합니다. 기존 같은 색 블록을 새 블록의 일부로 빌리는 경우를 거부합니다.
- 1.85/3.4/4.2칸 높이의 들어 올림을 검사합니다. 높은 들림은 관찰된 실제 높이라는 뜻이 아니라 기존 탐색 제한을 재현하기 위한 제어 조건입니다.
- 위치 측정 실패 시 잡기/판 정렬을 구분합니다. 조작 전/실패 직전 두 화면과 좌표를 메모리에서 보관하므로, 정지 후 앱으로 돌아가 **위치 측정 실패 진단 파일 저장**을 누르면 ZIP으로 저장할 수 있습니다. 화면 공유를 종료하기 전에 저장하세요. 새 자동 플레이를 시작하면 이전 기록을 비웁니다.
- ZIP에는 게임 화면이 들어 있습니다. 사용자가 저장을 선택할 때만 파일을 만들며, 앱이 자동으로 업로드하거나 다른 사람에게 보내지 않습니다. 새 권한을 추가하지 않습니다.

## 0.5.1 인식 이후 동작 수정

첨부 파일 `BlockBlastAuto-v0.4.1.apk`의 실제 내부 버전은 0.5.0입니다. 이번 APK의 파일명·앱 표시·manifest 버전은 0.5.1로 통일합니다.

- 실제 보라색 이벤트 테마 스크린샷에서 초록 블록의 금색 테두리를 다른 색의 가림으로 오인해, 판만 인식한 채 계속 대기하던 문제를 재현했습니다. 얇은 테두리/그림자와 넓은 미확인 면을 구분합니다.
- 금색 프레임이 두꺼운 테마에서는 컬러 면 너비가 실제 칸 간격보다 작습니다. 분리된 면의 중심 간격을 사용하고, 축소로 면이 붙으면 전체 마스크 범위를 사용해 일부 셀을 누락하지 않습니다.
- 실제 스크린샷의 보드 64칸·초록 가로2·빨강 엇갈린4·주황 T4와 합법적인 배치 계획을 회귀 검사합니다. 격자만 찾은 것을 전체 손패 인식 완료로 표시하지 않습니다.
- 빈칸 기준은 중앙과 네 모서리의 일관성으로 확인합니다. 어두운 점유 칸을 기준으로 판이 반전되는 모호한 경우는 거부합니다. 회색 및 같은 색상각의 다른 명도 가림도 계속 검사합니다.
- 화면 안정화, 배치 계산, 블록 잡기, 입력 거부/취소를 별도로 표시합니다. 최신 브랜치의 접근성 루트가 null인 SurfaceView 게임 처리도 유지합니다.
- 에뮬레이터 테스트는 금색·어두운 색·금색 테두리 보라색의 별도 제어용 판을 사용합니다. 실제 Block Blast 게임을 실행한 시험과 다릅니다.

## 0.4.1 인식 오류 수정

- 게임판과 아래 블록이 보이는데도 “게임판 미검출”이라는 하나의 문구만 표시하던 문제를 수정했습니다. 이제 격자, 판의 특정 셀, 1~3번 블록, 검은 캡처 화면을 구분합니다. “판 인식됨 · 2번 블록 인식 대기”는 블록이 없다는 의미가 아니라 해당 모양을 확실히 읽지 못했다는 의미입니다.
- 밝기 상한 채널 값이 150 이하면 컬러 블록을 거부하던 조건을 완화했습니다. 각 보관함의 주된 표면 색과 색상각을 측정해 그림자가 인접 셀을 하나로 이어 붙이지 않게 합니다.
- 회색/다른 색의 가림, 불완전한 셀, 모르는 보관함은 계속 조작하지 않습니다. 인식 실패 단계의 세부 코드는 `BlockBlastAuto` 로그에 남으며 캡처 이미지는 외부로 보내지 않습니다.
- 원본 게임 스크린샷의 색상을 바꾼 3개 어두운 팔레트 회귀 검사를 추가했습니다. 이는 실제 게임에서 새로 촬영한 스크린샷이 아닙니다. 사용자 기기의 이번 실패 원인이 해당 팔레트 문제와 동일하다고 확인한 것은 아닙니다.

## 변경된 동작

- 화면 비율만으로 좌표를 추측하지 않고 8×8 격자와 칸 간격을 찾습니다.
- 노란색 한 종류뿐 아니라 밝은 블록과 일부 어두운 컬러 블록을 인식합니다. 모양을 읽지 못한 보관함은 빈칸으로 넘기지 않고 해당 화면을 거부합니다.
- L자·대각선·긴 블록의 실제 셀을 읽고 **채워진 셀 내부**를 집습니다.
- 손가락을 유지하는 접근성 연속 제스처로 블록을 들어 올립니다. 드래그 중 확대된 블록을 화면에서 찾아 실제 위치 차이만큼 이동합니다.
- 정렬을 확인한 뒤 놓고, 줄 삭제 후 예상 게임판과 남은 보관함이 정확히 일치해야 다음 수를 진행합니다.
- 같은 보드가 그대로 남은 실패만 1회 재시도합니다. 위치 측정 실패, 잘못 놓인 결과, 터치 취소는 중단합니다.
- 이미 놓인 같은 색 블록이 새 블록의 일부로 섞이지 않도록, 정렬 확인은 목적지 주변의 새로 바뀐 픽셀을 요구합니다.
- 정지 요청은 대기 중인 마지막 UP을 기다리지 않고 현재 제스처를 취소합니다. 취소용 터치는 앱 소유의 비활성 상태 표시 영역에서만 처리합니다.
- 세 블록의 순서와 위치를 제한된 빔 탐색으로 계산합니다. 줄 삭제, 큰 빈 공간, 긴 빈 줄, 고립된 빈칸을 평가합니다. 전부 배치할 수 없더라도 가능한 부분 배치를 반환합니다.
- 캡처 이미지는 최대 720픽셀 너비로 한 번 복사합니다. 행 패딩과 마지막 행의 짧은 버퍼를 처리하며, 하드웨어 버퍼나 Bitmap을 보관하지 않습니다.

기존 수동 `dragYOffset` 설정은 사용하지 않습니다. 실제 블록 위치를 측정할 수 없으면 임의의 Y 보정값으로 계속 조작하지 않습니다.

## 검증 범위와 한계

원본 게임 스크린샷 2장, 크기/위치 변화, 여러 색, 모호한 화면 거부, 실제 RGBA 버퍼, 합법 배치/동시 줄 삭제와 시뮬레이션은 `bash tools/check-core.sh`로 검사합니다.

`AutoplayDeviceTest`는 Android 에뮬레이터에서 실제 MediaProjection과 AccessibilityService를 사용합니다. 별도 디버그용 테스트 판이 블록을 손가락 위로 띄우므로 이미지 측정, 정렬, 연속 설치와 중단을 검증할 수 있습니다. **이 판은 실제 Block Blast가 아닙니다.** 테스트 Activity는 외부에 공개하지 않으며 런처 메뉴에도 표시하지 않습니다.

실제 게임 앱과 사용자의 실기기에서는 검증하지 않았습니다. 게임 버전, 흐린/어두운 블록, 이펙트, 고스트 미리보기, 가려진 보관함, 분할 화면 및 다른 격자 스타일은 인식되지 않을 수 있습니다. 특정 점수나 무한 생존을 보장하지 않습니다. 인식이 불확실하면 멈추는 방향을 우선합니다.

## 빌드와 테스트

JDK 17, Android SDK 35, Gradle 8.9를 사용합니다.

```sh
bash tools/check-core.sh
gradle :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
# 에뮬레이터에서만 실행: 테스트 대상 접근성 설정을 변경합니다.
bash tools/device-check.sh
```

[브랜치의 GitHub Actions](https://github.com/shinminjun06/youtube-skipper/actions?query=branch%3Ablockblast-auto-build)에서 **Build BlockBlast APK** 실행을 열고 `BlockBlastAuto-debug-apk`와 `BlockBlastAuto-verification`을 다운로드합니다. ZIP 안의 APK를 압축 해제해 설치합니다.

배포 파일은 디버그 서명입니다. 이전 개발 APK와 인증서가 달라 설치가 거부되면 기존 Block Blast Auto를 제거한 뒤 설치해야 할 수 있습니다. 게임 앱이나 게임 저장 데이터는 변경하지 않습니다.
