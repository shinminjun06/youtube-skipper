# Block Blast Advisor + Auto v1.3.7

Android 11+ 전용 오프라인 Block Blast Classic 게임판 분석 앱입니다. **추천 모드**와 **자동 플레이 모드**를 같은 앱에서 선택할 수 있습니다.

- **기본값: 추천** — 현재 판과 손패에 맞는 추천 위치를 테두리로 표시하고 사용자가 직접 블록을 놓습니다. 게임에 자동 터치를 보내지 않습니다.
- **모드: 자동** — 사용자가 의도적으로 선택하고 ▶ 시작을 누른 경우에만 AccessibilityService가 게임에 드래그를 전송합니다. 블록을 잡았는지, 위치가 맞는지, 실제 놓인 블록과 게임판이 예상과 일치하는지를 차례로 검증합니다.
- 불확실한 화면, 잘못된 설치, 전체 손패 배치 불가능, 앱 전환, 제스처 취소, 시간 초과 시 자동 조작을 **중지**합니다. 게임 오버 없이 무제한 플레이를 보장하지 않습니다.

개발 브랜치: `blockblast-autoplay-build`. 기존 **추천 전용 v1.2.0**의 소스는 `blockblast-auto-build` 브랜치에 그대로 보존했습니다. 기본 `main` 브랜치는 변경하지 않습니다.

## 사용법

1. [오토플레이 전용 빌드 페이지](https://github.com/shinminjun06/youtube-skipper/actions?query=branch%3Ablockblast-autoplay-build)에서 **Build BlockBlast Advisor + Auto APK**가 초록 체크로 완료된 실행을 열고 **BlockBlastAutoPlay-apk** ZIP을 다운로드합니다. ZIP을 풀고 **BlockBlastAutoPlay-v1.3.7.apk**를 설치하세요. 구버전과 혼동하지 마세요.
2. 홈 화면에서 **Block Blast AutoPlay** 아이콘을 실행해 **v1.3.7**이라고 표시되는지 확인합니다. 기존 **Block Blast Advisor**(v1.2)는 다른 앱으로 남아 있습니다. 기존 Advisor의 접근성 서비스를 끄고 **Block Blast AutoPlay** 접근성을 연결한 다음 **전체 화면 공유 시작**을 승인합니다.
3. 앱 첫 화면에서 **자동 플레이 모드 선택**을 누른 뒤 Block Blast Classic의 세로 화면을 엽니다. 자동 모드에서는 하단에 고정되는 플로팅 창에서도 **모드: 추천** 또는 **모드: 자동**을 전환할 수 있습니다.
4. **▶ 시작**을 누릅니다. 추천에서는 초록색 칸을 보고 수동으로 놓습니다. 자동에서는 플로팅 창이 사라지고, 앱이 블록을 잡고 설치를 검증합니다. 조작창이 숨겨져 있는 것은 정상입니다.
5. **자동 플레이 중에는** Android 알림 패널의 **종료** 버튼으로 즉시 중지하세요. 중지되면 플로팅 창이 다시 나타납니다. 추천 모드에서는 기존 ■ 중지 버튼을 이용할 수 있습니다.
6. 추적 실패 시 앱의 **위치 측정 실패 진단 파일 저장**을 이용해 원인 분석용 ZIP을 저장할 수 있습니다.

## v1.3.7 실제 이동한 빨간 블록을 놓치는 오류 수정

- 사용자가 올린 v1.3.6 진단 ZIP은 `PICKED / NO_HELD_MATCH`. 게임판이 차 있는 상태에서 **2번 빨간색 4칸 L 조각**을 집어 움직였지만, 앱은 움직임 확인에 실패했습니다.
- **진단 PNG의 실제 시간 순서**는 `before.png → probe.png → held.png`입니다. `probe.png`의 확대된 빨간 L 원점 약 `(340,1034)`이 `held.png`에서 약 `(262,1034)`으로 **왼쪽 78픽셀** 이동했습니다. 명령한 왼쪽 52픽셀과 방향이 맞습니다.
- 실패 원인은 **원래 대기 중인 작은 빨간 L의 색상과 확대된 블록이 겹쳤기 때문**입니다. 현재 블록 중심 4개 중 2개가 집기 전 사진의 빨간색과 이미 일치하여, 모든 중심이 새로 바뀌어야 한다는 기존 추적 조건이 실패했습니다.
- 기본 탐색의 엄격한 색상·형태 검사는 유지합니다. 최초 이동 검증이 실패하여 **반대 방향으로 한 번 재측정하는 상황에만** 완전한 모양, 절반 이상의 새로운 중심, 55% 이상의 새로운 색상 표본, 실제 명령 방향과 일치하는 움직임을 함께 검사하여 재탐색합니다.
- 손가락 주변 넓은 검색 영역을 검사하여 **동일한 모양의 후보가 두 개 이상이면 성공 처리하지 않습니다**. 이 복구는 집힌 블록을 다시 찾는 데만 사용되며, 목표 위치에 블록을 놓기 전에 수행하는 엄격한 검증과 실제 설치 후 게임판 검증은 변경하지 않았습니다.
- 업로드된 개인 게임 화면은 저장소에 공개하지 않았고, 해당 좌표·대기 블록 겹침과 안전 실패 사례를 합성 데이터 회귀 테스트에 추가했습니다.
- CI 테스트/빌드가 통과해도 실제 휴대폰에서 연속 자동 배치가 보장되지는 않습니다.

## v1.3.6 긴 블록이 플로팅 창에 가려지는 오류 수정

- 사용자가 제공한 **v1.3.5 진단 ZIP**은 `NO_HELD_MATCH / PICKED`이며, 실제로 블록을 못 잡은 게 아닙니다. **파란색 세로 5칸 블록**은 처음 잡힌 뒤 약 한 칸(78px) 이동했지만, 화면 오른쪽 아래의 불투명한 플로팅 창이 아래 **2칸의 중심**을 가려 5칸 전체 형태 검증을 통과할 수 없었습니다. 명령은 52px 왼쪽, 실제 블록도 왼쪽으로 움직인 증거가 있습니다.
- 하단 또는 상단에 패널을 옮기는 기존 대응은 특정 모양/위치의 다른 블록을 다시 가립니다. **자동 모드의 ▶ 시작 이후에는 불투명한 조작창과 추천 테두리 모두 Android 화면 및 화면 캡처에서 숨김 처리**합니다. 자동 실행이 멈추거나 중단되면 조작창을 다시 표시합니다. 추천 모드는 종전처럼 하이라이트와 조작 버튼을 유지합니다.
- 자동 실행 중 긴 블록이 가려지지 않도록 캡처를 정리하면서도, **모든 조각 중심에 대한 엄격한 움직임 확인**과 **실제 놓은 뒤 보드 검증**은 그대로 유지합니다. 흐릿하거나 불완전한 블록을 무조건 성공 처리하지 않습니다.
- **자동 모드를 멈추려면 Android 알림 패널의 `Block Blast Advisor + Auto` → `종료`**를 이용하거나 앱을 열어 `정지`를 누르세요. 숨긴 플로팅 창을 누르는 방식으로 멈출 수는 없습니다. 안전 취소 시 숨긴 패널의 옛 좌표 대신 시스템 화면 모서리에 종료 제스처를 보내 게임판에 불필요한 탭을 만들지 않습니다.
- 사용자 스크린샷을 공개 저장소에 올리지 않았으며, 합성 화면 회귀 검사와 Android 기기용 UI 숨김/복원 테스트를 추가했습니다. **실제 게임에서 연속 자동 설치가 성공하는지는 아직 검증되지 않았습니다.**

## v1.3.5 세로 2칸 블록 잡기 오류 수정

- v1.3.4 사용자 진단 ZIP의 **NO_HELD_MATCH / PICKED** 상황: 빈 게임판의 보라색 세로 2칸 블록을 정상적으로 잡았고, 진단 영상에서 블록 외곽의 가로 좌표는 `511..587 → 433..509`로 **78픽셀 왼쪽 이동**했습니다. 앱에서 요청한 이동은 약 `52픽셀`이었습니다.
- 기존 탐색기는 이전 손가락 위치 `416`에서 오른쪽으로 **1칸(약 80픽셀)**까지만 검색해 블록 원점 `511`을 놓쳤습니다. 실제 블록 움직임은 정상인데도 **잡지 못했다고 판단**했던 문제입니다.
- 보통은 원래의 빠른 손가락 근처 검색 범위를 사용하고, 찾지 못한 경우에만 **왼쪽 추가 2.5칸, 오른쪽 3칸까지 넓혀 재검색**합니다. 손가락 대비 게임의 가로 드래그 보정값이 달라도 새로 나타난 실제 조각을 찾도록 했습니다.
- 넓혀 찾았더라도 조각의 색상, 전체 모양, 새로 생긴 화면 픽셀, **명령한 이동 방향과 크기**가 모두 일치해야 잡기 성공으로 인정합니다. 정지된 조각·반대 방향 이동은 인식하지 않습니다.
- 진단 이미지 원본은 공개 GitHub에 넣지 않고, **해당 720×1560 좌표와 블록 이동을 합성한 테스트**로 회귀 확인합니다. 실제 게임에서 끊김 없는 자동 플레이 성공률은 아직 실기기 검증이 필요합니다.

## v1.3.4 노란색 T자 블록 추적 오류 개선

- 진단 ZIP v1.3.3의 `NO_HELD_MATCH / ALIGN`은 한 번의 드래그 이후 노란 T자 블록이 게임판보다 높이 올라가고, 플로팅 상태 창이 블록의 **4개 중심 중 3개를 가린 상황**입니다. 실패 당시 좌표는 손가락 약 `(346,574)`, 블록 약 `(326,35)`, 목표 `(361,366)`이었습니다.
- 자동 모드에서는 플로팅 조작창을 **화면 최하단(블록 트레이 아래)**으로 자동 이동합니다. 상태 메시지가 길어져 창 높이가 바뀌어도 다시 하단에 맞춥니다. 자동 입력 중에는 플로팅 창 드래그를 잠급니다. 정지 버튼은 계속 누를 수 있습니다.
- 기존 보정은 목표-현재 블록 오차를 한 번의 손가락 이동으로 그대로 전달했습니다. **최대 2칸, 오차의 62%씩 단계 보정**하도록 변경해 큰 점프가 게임의 손가락-블록 수직 간격을 왜곡해 화면 위로 날아가는 일을 줄입니다. 최대 10회 보정과 14.5초 제스처 안전 타임아웃을 적용합니다.
- 노란 T자 블록 가림 및 과도한 이동을 **사용자 스크린샷을 공개하지 않은 합성 테스트**로 확인합니다. 인식이 불확실하면 블록을 놓지 않고 정지하는 기존 안전장치를 유지합니다.
- 자동 모드와 별개의 추천 전용 앱은 변경하지 않았습니다. **실제 기기에서 연속 성공은 아직 추가 검증이 필요**합니다.

## v1.3.3 자동 플레이 정렬 보정

- 사용자가 보내준 v1.3.2 진단 ZIP은 `CORRECTION_LIMIT / ALIGN`으로, 주황색이나 파란색 블록이 아닌 **보라색 2×2 블록**을 **5번 보정하고도** 끝내 놓지 못한 상황입니다.
- 실패 스크린샷에는 조각이 목표 5열·2행의 네 칸을 이미 덮고 있었습니다. **올려준 실제 영상 프레임을 오프라인 색상 비교한 결과 목표 내부 16/16 지점이 실제 보라색 조각 색상과 일치**했지만, 그림의 윗변은 게임이 목표보다 약 18픽셀 위에 그렸습니다.
- `DragAlignment.targetCellPreview`는 **배치 가능성 + 4개 조각 칸 내부의 16개 색상/변화 검사**를 결합합니다. 블록 그림이 목표에서 최대 0.32칸 벗어나도 **목표 인근 추적이 유일하고 180ms 이상 안정적**이며 네 칸 모두 올바른 색상으로 덮인 경우에만 놓습니다.
- 다른 칸에 있거나 0.55칸 이상 벗어난 조각, 다른 색상이나 정지된 그림은 조작을 승인하지 않습니다. 놓은 뒤에는 여전히 실제 게임판/손패를 검증하고 틀리면 자동 플레이를 중단합니다.
- 실패 진단 ZIP에 마지막 추적 좌표와 목표 칸 미리보기 인식 여부를 기록해 다음 장애 진단이 더 명확해졌습니다.
- 업로드한 개인정보 포함 가능성이 있는 실제 스크린샷 파일은 GitHub에 공개하지 않고, 합성 화면으로 회귀 테스트를 작성했습니다.

## v1.3.2 정렬 실패 수정

- 실제 사용자가 업로드한 v1.3.1 진단 ZIP의 `ALIGN / NO_HELD_MATCH` 사례를 조사했습니다. **보라색 2×2 조각은 실제로 들려 있었으나 약 (523, 273)에 표시되어 목표 (440, 524)와 멀었습니다.** 기존 코드는 목표 부근만 검색했습니다.
- 정렬 중 목표 인근에서 블록을 못 찾을 때는 **전체 손에 들린 영역을 다시 검색**해 위치를 재보정합니다.
- 플로팅 상태 창이 블록 첫째 줄을 가린 경우 36개 색상 표본 중 6개가 가려져도, **모든 블록 중심부가 새로 나타났고 외곽 경계가 정상인 경우에만** 복구 위치를 허용합니다.
- **실제 블록 놓기에는 이전과 같은 엄격한 목표 위치 일치 검사가 반드시 필요**합니다. 복구용의 느슨한 검색 결과만으로 블록을 놓지 않습니다.
- 개인정보가 담길 수 있는 진단 스크린샷은 저장소에 넣지 않고 **합성 회귀 테스트만** 추가했습니다.
- 코어 및 APK 빌드는 CI 결과로 확인하고, 실제 기기 성공률은 추가 검증이 필요합니다.

## v1.3.2 변경 사항

- **설치 혼동 방지:** 앱 ID를 `com.pivotry.blockauto.autoplay`로 분리했고, 설치 앱 이름을 **Block Blast AutoPlay**로 변경했습니다. 기존 추천 전용 `com.pivotry.blockauto`는 그대로 남습니다. Android 접근성 설정에서 두 서비스를 동시에 켜지 마세요.
- **명확한 모드 버튼:** 플로팅 창뿐 아니라 앱 첫 화면에도 **자동 플레이 모드 선택 / 하이라이트 추천 모드 선택** 버튼을 추가하고, `현재 모드` 상태를 표시합니다.
- **버전 표시:** 앱 첫 화면과 APK 파일명에 **v1.3.2**이 명시됩니다. v1.2 화면이 뜬다면 여전히 기존 Advisor 앱을 실행한 것입니다.


- v1.2.0의 3개 손패 탐색, 콤보 점수 근사 및 생존 평가, 기기 내 **COMBO** 텍스트 자동 인식을 계승합니다. 다른 버전에서는 실제 점수 규칙이 다를 수 있습니다.
- 기존 v1.0.0의 Android 이어붙이기 드래그 제스처를 **선택형 자동 모드**로 복원했습니다. 기본 모드에서는 자동 터치가 불가능하도록 실제 동작부에서 검사합니다.
- 이전 진단의 **52px 요청 / 약 78px 렌더 이동**처럼 게임의 조각이 칸 단위로 보정되어 움직여도 잡힌 블록 전체의 방향·위치가 일치하는지 검증합니다. 정지된 트레이나 미리보기만으로는 손에 잡았다고 판단하지 않습니다.
- 이동하는 블록의 목표 위치를 재관측하고, 위치를 보정한 후에만 손가락을 놓습니다. 배치 이후 게임판과 남은 조각이 예상과 일치하지 않으면 멈춥니다.
- 추천 모드에서는 하이라이트 픽셀을 캡처에서 보정하고, **변화 없는 게임판을 반복 계산하지 않도록 캐싱**합니다.
- 메인 앱 내 콤보 수동 입력이 필요하지 않습니다. OCR이 놓치는 순간에는 기존 확인된 배치 기록으로 콤보를 추적합니다.

## 검증과 한계

- `bash tools/check-core.sh` — Java 17: 실제 화면 인식, 이동량 오차, 고득점 탐색, 점수 텍스트 보호, 진단 ZIP 회귀 테스트
- `gradle :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug` — Android SDK 35
- `.github/workflows/gesture-integration.yml` — 수동 실행하는 Android 에뮬레이터 제스처 통합 검사
- **빌드 성공과 코어 테스트 통과만으로 실제 휴대폰 게임에서 터치 성공이 입증되는 것은 아닙니다.** 게임 버전, UI 크기, 화면 공유 렌더링과 애니메이션에 따라 추가 조정이 필요할 수 있습니다.
- 앱에서 사진이나 텍스트를 외부 서버로 전송하지 않습니다. ML Kit의 텍스트 인식 모델은 APK에 포함됩니다. Android 루트가 필요하지 않습니다.
